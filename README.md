# Faceless Content Machine

Private, fail-closed automation for one English **Unbelievable but True History** vertical Short per run. It researches a topic, creates and verifies a script with Gemini, downloads licensed Pexels footage, narrates locally with Piper, burns timed captions with FFmpeg, validates the MP4, and can upload directly to YouTube and TikTok.

The daily cron is intentionally **not active yet**. Public publishing is also code-locked. Both remain disabled until the real private upload test passes.

**Commissioning status:** the first GitHub-hosted QA run was blocked before a runner started because the account has an Actions `$0` budget with **Stop usage** enabled. The local suite passes, but cloud execution cannot be claimed operational until that account-level constraint is resolved. Making this secret-free code repository public is the zero-spend route because GitHub documents standard runners as free for public repositories.

## Architecture

```text
GitHub Actions
  -> curated/Wikimedia research with two reachable evidence sources
  -> Gemini structured script + independent evidence-only verification
  -> Pexels portrait video search (4-6 distinct clips)
  -> local Piper TTS + per-caption WAV timing
  -> FFmpeg 1080x1920 render with burned captions
  -> ffprobe/audio/black-frame/caption visibility validation
  -> direct YouTube Data API and TikTok Content Posting API uploads
  -> persistent data/content_history.json
```

There is no Buffer, Cloudinary, paid TTS, paid host, database, or always-on process. GitHub Actions is the eventual scheduler. TikTok uses `FILE_UPLOAD`, so temporary public media hosting is unnecessary.

## Safety state

- `PUBLISH_MODE=dry-run` is the default.
- `PUBLISH_MODE=private` uploads only private content.
- `PUBLISH_MODE=public` also requires `ALLOW_PUBLIC_PUBLISH=true`.
- Fixture QA can never publish, even if platform flags are accidentally set.
- A topic is marked `published` only after every enabled destination succeeds.
- Any missing secret, failed fact check, fewer than four clips, TTS/render error, invalid stream, bad duration, silent audio, blank span, or invisible caption fails the job with a non-zero exit.
- The production workflow has no cron until private destination QA passes.

## Workflows

### QA

`.github/workflows/qa.yml` runs on pushes, pull requests, and manually. It needs no secrets. It executes unit tests and a deterministic 30-second 1080x1920 render, then keeps the test video and validation metadata for seven days.

### Produce one Short

`.github/workflows/produce.yml` is currently manual only. Its inputs permit `dry-run` and `private`; public is absent by design during commissioning. It caches the Piper voice and commits content history after every real attempt.

From GitHub: **Actions -> Produce one Short -> Run workflow**.

## Required GitHub Actions secrets

Add only the names needed for the selected stage under **Settings -> Secrets and variables -> Actions**. Never commit their values.

| Stage | Secret names |
|---|---|
| Generation | `GEMINI_API_KEY`, `PEXELS_API_KEY` |
| Private YouTube upload | `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_REFRESH_TOKEN` |
| Private TikTok upload | `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `TIKTOK_REFRESH_TOKEN` |

The TikTok code also accepts a short-lived `TIKTOK_ACCESS_TOKEN` locally, but GitHub production should use a refresh token.

## Local verification

Requirements: Python 3.11+, FFmpeg with libass, and DejaVu Sans.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
python -m faceless_machine.pipeline --fixture
python scripts/download_piper_voice.py
```

A real generation-only run is:

```bash
export GEMINI_API_KEY=...
export PEXELS_API_KEY=...
PUBLISH_MODE=dry-run python -m faceless_machine.pipeline
```

Do not put the values in shell history on a shared machine. GitHub Actions secrets are the production location.

## Content and evidence rules

- Scripts are 70-120 words and the exact hook is the first sentence.
- Gemini receives evidence text and is explicitly prohibited from adding unsupported numbers, dates, quotations, motives, causal claims, or superlatives.
- A second zero-temperature verification call rejects unsupported claims and misleading hooks.
- Curated topics require two reachable source domains. When the curated list is exhausted, Wikimedia's dated historical feed is used with its linked Wikipedia and Wikidata records; the script remains limited to the supplied event facts.
- History records the script, hook, sources, visual searches, footage credits, validation report, platform IDs, state, and errors. Failed items are never marked published.

Pexels creator names and source URLs are retained in the internal metadata. YouTube descriptions generated by Gemini include source references. Pexels attribution should also be surfaced in descriptions before public launch.

## Current platform constraints

- **TikTok:** Direct Post requires an approved app, the `video.publish` scope, and user authorization. Unaudited clients can post only privately. TikTok's official Direct Post guidance also requires user-provided metadata and explicit consent before sending a post. A zero-touch public cron cannot be claimed compliant until TikTok approves the exact workflow in audit.
- **YouTube:** new/unverified API projects can be limited to private uploads until the API project passes YouTube's compliance audit. Private commissioning remains supported.
- **Partial cross-platform failure:** neither platform supports a distributed transaction. If the first destination accepts a video and the second rejects it, history records the successful platform ID plus the failure for manual recovery; the item is not marked fully published.

## Troubleshooting

- `Required secret ... is not configured`: add the named Actions secret; do not paste it into logs.
- `No generateContent Flash model`: leave `GEMINI_MODEL` unset so discovery can select an available model, or configure a model returned by the key's ListModels response.
- `Only N valid distinct clips`: adjust visual queries or rerun; publishing is skipped.
- `duration ... outside 25-45s`: the narration is rejected before upload; revise the script/voice pacing.
- `burned captions ...`: FFmpeg's generated caption proof was blank or off-screen; publishing is skipped.
- `TikTok ... private`: expected before Content Posting API audit.
- A failed run can be rerun manually. The date is blocked only after a fully successful publication.
